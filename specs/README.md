# Feature Specifications

Use one Spec Kit directory per non-trivial, user-visible, contract, data,
security, dependency, deployment, or architecture change.

The feature spec is the single source of change intent. Feature research, plan,
data model, contracts, quickstart, and tasks remain in that directory; do not
create a parallel `docs/01` through `docs/06` planning chain.

Durable cross-feature product boundaries, ADRs, security architecture, and
standards remain under `docs/`.
